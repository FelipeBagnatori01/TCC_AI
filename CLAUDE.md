## Project

Undergraduate thesis (UNIFESP): LSTM failure detection/prediction on telecom observability KPIs, SHAP/LIME explainability, and an LLM agent that explains the root cause (timestamp, component, reason) — evaluated on the public OpenRCA benchmark (Telecom subset is the main scenario).

The full spec lives **outside** this repo: `../instrucoes_implementacao_tcc.md` (Portuguese; stages E0–E9, research questions, invariant rules R1–R11). Read it before starting a stage. Progress notes: `../acompanhamento_etapas_tcc_1.md`.

**Workflow rule from the spec:** work one stage at a time, in order. At the start of a stage present the plan and open questions before writing code; at the end report summary, changed files, how to run, acceptance criteria with evidence, ADRs, blockers, and wait for approval. Never mark a criterion met without evidence; never skip/silence tests or relax lint. Do not assume OpenRCA file or column names — inventory them (E1). Missing data/access goes to `docs/BLOQUEIOS.md`, not invented.

## Architecture (E0 infrastructure)

Everything experimental flows through three pieces that must be used together to satisfy the reproducibility rules (R5–R7):

- **Config** (`config.py`): pydantic v2 models, `extra="forbid"` and frozen. `load_config(*yamls, overrides=...)` deep-merges files then overrides; an unknown key at any depth is a hard error. Adding a config field means adding it to the model *and* `configs/base.yaml`. Tests redirect all output paths to `tmp_path` via the `config` fixture in `tests/conftest.py`.
- **Run tracking** (`tracking.py`, `env.py`, `seed.py`): `Run(config)` is a context manager that creates `experiments/<timestamp>-<name>/` (config.resolved.yaml, provenance.json with commit/config/dataset hashes and hardware, run.log, metrics.json, artifacts/) and **seeds Python/NumPy/PyTorch and enables `torch.use_deterministic_algorithms(True)`**. Dataset hash comes from the versioned `data/MANIFEST.csv`. Metrics that must be reproducible across runs go in `metrics.json`; anything that depends on cache state or wall-clock (LLM cost/latency) goes in artifacts, so two same-seed runs produce byte-identical `metrics.json`.
- **LLM client** (`llm/`): `LLMClient` wraps an `LLMProvider` (Protocol with `complete(request) -> ProviderResult`) chosen by name via a registry (`register_provider` / `build_provider`). Providers: `fake`, `fake_agent` (scripted offline agent, registered by `tcc_rca.agent.run`), `anthropic` and `openai` (lazy SDK import; keys from `.env`, loaded by the CLI); swapping is a config change (`configs/llm/*.yaml`). Requests carry tools, a response JSON schema, effort and a repetition index `sample`, all in the cache key; assistant turns keep the provider's raw output items and the same adapter replays them unchanged (reasoning/thinking must be preserved). Current models reject `temperature`: never send sampling parameters; reproducibility is the cache, variance is `sample`. Cache key = SHA-256 of canonical JSON of (provider, model, messages, temperature, max_tokens) — anything affecting output must be in `LLMRequest`. Cache hits cost 0, skip the provider and budget check, but are still logged to the JSONL call log. Budget cap is checked *before* each paid call (one call may overshoot).

## Data layout (E1)

- OpenRCA repo is a git submodule at `external/OpenRCA` (pinned commit in ADR 0003; excluded from ruff; never edit it — run ruff/format only via `make`, not on `external/`). Clone with `--recurse-submodules`.
- Raw Telecom data lives outside the repo (`../Telecom`) and is symlinked at `data/raw/openrca/Telecom` (git refuses paths beyond that symlink, so gitignore tests use `Bank/`). Real Telecom facts (6 h/day 00:00–06:00 UTC+8, 15 days, 60 s metric step, near-duplicate days) are in `docs/DICIONARIO_DADOS.md`.
- `ingestion/timeutil.py` is the only place that converts UTC+8 ↔ UTC (ADR 0002). `ingestion/cases.py` exposes agent-visible query data only; ground truth (`scoring_points`) is read solely via `ingestion/labels.py`, which `tcc_rca.agent` must never import (tested).
- E2 series (ADR 0005/0006): features are named `component::kpi`; every KPI must have an entry in `configs/data/kpi_catalog_telecom.yaml` (including `item_agg` for multi-item KPIs) or the build fails. `FeatureSelector`/`RobustScaler` take a boolean `train_rows` mask and must only ever be fitted on training rows (leakage test in `tests/test_series_transforms.py`). The `disponibilidade` KPI category is exempt from constancy dropping; that choice was made after seeing labels, so every headline metric from E3 on must also be reported with the control `configs/experiment/sensitivity_sem_isencao.yaml` (threat log: `docs/AMEACAS_VALIDADE.md`). Dependency edges merge trace calls with `AppTelecomDeploymentList.xlsx` (symlinked under `data/raw/openrca/`).
- E3 (ADR 0007-0009): detection framing (H=0, no precursor found), W=20, D=5; windows never cross days; labels 1/0/null (null = near a failure but outside the positive band; never trained on as normal nor scored). Days 2020_04_21/22/23 are unlabelled copies of May days and are excluded everywhere; 2020_04_11 + 2020_04_20 are the initial train/val block, so evaluation uses the 45 May failures over 10 rolling-origin folds (one test day each, last prior day = validation). `tcc_rca.dataset` reads `record.csv` and is ground truth: the agent-isolation test forbids it, `read_failures`, `build_cases`, `record.csv` and `windows.parquet` in `tcc_rca.agent`. Day strings in YAML must be quoted (YAML reads `2020_04_21` as an integer).
- E4 (ADR 0010): `tcc_rca.evaluation` holds every metric (hand-computed tests in `tests/test_metrics.py`), cluster bootstrap CIs and the official-scorer wrapper (`evaluation/openrca.py` writes a filtered `query.csv` into the run dir and calls `main.evaluate`; never reimplement it). Per fold, selection/z/robust scaling fit only on normal minutes of training days; thresholds come from the validation day (best F1, or the 0.99 quantile of normal validation scores when it has no failure). Report event recall only next to its chance level (`event_recall_by_chance`): with tens of false alarms per hour it is meaningless. LightGBM must stay `num_threads=1` (multithreaded LightGBM aborts with an OMP error once torch's libomp is loaded, which `Run` does). `sklearn` has a scoped mypy `ignore_missing_imports`.
- Bank series (ADR 0012): the initial block 2021_03_04–05 (`series.initial_block_days`) is the only data used to fit drain3 log templates, native sampling steps (adaptive per-feature forward fill, Bank only) and the provisional drop report; Bank E3 must test from 2021_03_06. The Bank KPI catalog is rule-based (ordered regexes, `KpiCatalog.lookup`); container KPIs drop the restart hash. Each day's data is clipped to its UTC+8 calendar day. Count features (`series.logs.is_count_kpi`) are zero-filled.
- Bank E3 (ADR 0013): same task definition as Telecom (W=20, H=0, D=5); first test day 2021_03_06 (8 folds, 120 failures); E3 refuses to run if its initial block differs from `series.initial_block_days`. `with_roles(windows, fold, guard_minutes)` purges train/val windows ending within W+H minutes before the test day (needed for contiguous Bank days; no-op in Telecom); never purge true overlaps. Precursor results have a `method` column: `global` (initial-block scaler, saturates on Bank drift) and `local` (causal 60-min rolling baseline, `dataset.precursor.local_abs_z`).
- E4 additions (ADR 0014): detector `zscore_local` and localizers `zscore_local` + `prior` (training-frequency reference) in both systems; metrics keys `localization` (global), `localization_local`, `localization_prior`. Localization ranks artifacts have a `method` column. Run dirs are not named by system: use the `run_dir` recorded in `reports/tables/baselines_<system>_<name>.json`.
- E5 (ADR 0015): `models/lstm` (ForecastLSTM trained on NORMAL train windows only, early stopping on normal val windows; ClassifierLSTM with pos_weight) and `evaluation/lstm.py` (validation-only grid search, 5 final seeds, models saved under `experiments/<run>/artifacts/models/fold*/seed*/`). `ForecastScorer.score(window)` is the pure function E6 explains. Normalization (`global` robust/clipped vs causal `local`) is a searched hyperparameter; `local` won in both systems. Claims "LSTM beats X" must come from `evaluation/compare.py` paired bootstrap verdicts, not from overlapping CIs. Never run a LightGBM fit and multithreaded torch in the same process (OpenMP crash on macOS): LightGBM is imported lazily and torch tests use 1 thread.
- E6 (ADR 0016): `explain/functions.py` re-implements the E5 forecast score in torch (must equal `ForecastScorer`, tested) and wraps the classifier probability; `explain/attributions.py` (SHAP GradientExplainer, LIME per `component::kpi` series, captum IG); `explain/evidence.py` builds the agent's evidence packages from agent-visible data only (window picked by the detector inside the query window, never the labelled onset; import guard tested); `evaluation/xai.py` measures XAI localization on oracle windows (paired vs E5 native and E4 heuristics), fidelity (insertion is relative to the FULL window score), stability and SHAP×LIME agreement; suggested-category hit is reported next to the training prior and uniform chance. Evidence packages: `explain.evidence_detector` (classifier) picks the window and alarm, `explain.evidence_explained` (forecaster) supplies the cited attributions, because classifier explanations are unstable across seeds (post-test decision, threat 11). Attribution is not causation; the suggested category never beats the prior, so the agent must reason over KPIs. CPU and MPS give the same attributions at similar speed; CPU is the default.
- E7 (ADR 0017): `tcc_rca.agent` = fixed read-only tools (`tools.py`) over `TelemetryStore` (`store.py`), whose allowlist is exactly series.parquet, the feature catalog, the dependency edges and the E6 evidence dir of one system (paths resolved; record.csv/query.csv/windows.parquet unreachable, tested). Never write those ground-truth file names as literals in `src/tcc_rca/agent` (the import/literal guard in `tests/test_cases.py` fails). Variants: A1 telemetry tools (incl. `find_anomalous_kpis`, a heuristic scan, threat 17), A2 + `get_evidence` (score/alarm/native ranking), A3 + SHAP/LIME C#/K#; `suggested_category` is never shown. Answers: pydantic schema with Portuguese JSON keys (`causas`, `explicacao`, `evidencias_citadas`), validated against task fields/count/window/candidates and against the T#/C#/K#/N# ids actually issued; invalid answers are retried with the errors. Task fields/failure count are parsed from agent-visible text (verified against all 187 queries outside the package). Model/prompt choices are made on the pilot case set (queries before the first test day), never on the test set. Prompts live in `configs/prompts/` (hashed per run); candidates are copied from the OpenRCA agent prompts (tested).
- Alternative models (ADR 0018, `evaluation/alt_models.py`): same `Experiment` folds/masks, normalization searched, 8 configurations per model on validation only, `lstm.seeds` finals (logistic: 1 seed), E6 oracle windows/background/reference. Tabular models (`models/tabular.py`) read `tensor_statistics` of the SAME filled normalized windows as the LSTM (must equal E4 `window_statistics`); SHAP per series = sum of the 5 statistics' attributions (`explain/tabular.py`; TreeSHAP/linear SHAP exact on log-odds; Isolation Forest sign flipped so positive = more anomalous); LIME is E6's `lime_groups` for every model. TCN (`models/tcn.py`) is a classifier trained by `fit_window_classifier` (the E5 recipe; `train_classifier` wraps it unchanged). `family: tabular` and `family: tcn` are separate processes (LightGBM OpenMP vs. torch). The agent's evidence stays on the LSTM whatever the outcome (choosing by test results = selection on test, threat 19).
- Telemetry readers enforce explicit schemas and fail on header drift; unit tests use the synthetic systems in `tests/synthetic.py` (`make_system` = Telecom layout, `make_bank_system` = Bank layout), never real data.
- Multi-system ingestion (ADR 0011): each system has its own file layout in `ingestion/telemetry.py` (`files_for(system)`); never assume one system's columns for another. Bank metrics/logs use second epochs, Bank traces switch from ms to s on 2021-03-23 (`time_unit="auto"`), and every conversion checks that timestamps fall within the folder's day. Bank data is symlinked at `data/raw/openrca/Bank`; the gitignore test uses the non-linked `NotLinked/` path.

## Conventions and constraints

- Code, identifiers, docstrings in English; docs, ADRs, reports and LLM-agent explanations in Portuguese. Non-obvious decisions get an ADR in `docs/adr/`.
- Telemetry (`data/raw`, `data/interim`, `data/processed`), `experiments/*` (including the LLM cache), `.env`, and model weights are gitignored; only `data/MANIFEST.csv` is versioned. OpenRCA telemetry is CC BY-NC 4.0 and must never be committed. `tests/test_gitignore.py` guards this.
- Invariants that later stages must respect (tests required): no temporal leakage (chronological day splits with guard gap, rolling-origin for the 51 Telecom cases, transformers fit on train only, forward-fill only); no label leakage to the LLM agent (`record.csv`/ground truth unreachable by agent tools, prompts contain no test labels); OpenRCA timestamps are UTC+8; the agent must be compared to the constant baseline and to the same LLM without evidence; agent results are scored with the official OpenRCA script, not a reimplementation.
- Add a dependency together with the stage that needs it (shap/lime/captum came with E6, anthropic/openai with E7).
- Pre-commit runs ruff, ruff format check and mypy; ruff rule set is in `pyproject.toml` (line length 100).
